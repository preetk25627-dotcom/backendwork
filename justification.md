# Database Choice: PostgreSQL

Industrial supply-chain transactions are fundamentally about correctness — an inventory decrement and its matching ledger entry either both happen or neither does, and PostgreSQL's ACID guarantees enforce that at the engine level without any extra work from the application. The "single hot SKU" race condition that kills most naive implementations is handled cleanly by PostgreSQL's row-level `SELECT … FOR UPDATE SKIP LOCKED`, which locks only the contested asset row and lets every other read and write in the catalog continue without interruption. On the read side, PostgreSQL's partial covering indexes let the real-time dashboard run a pure index-only scan against a few tens of thousands of rows instead of millions, keeping dashboard latency well under 50 ms even as the catalog scales.
